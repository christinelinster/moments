# Security

## Authentication and sessions

- Email input is trimmed and normalized to lowercase before uniqueness checks, storage, or membership matching.
- Email validation checks syntax and domain-label constraints. It does not perform DNS or delivery verification.
- Passwords are stored only as salted `scrypt` hashes. Plaintext passwords are not persisted.
- Sessions use 32-byte opaque random bearer tokens. The database stores only their SHA-256 hashes.
- Session tokens are sent in an HTTP-only cookie with `SameSite=Lax`, `Secure` in production, a root path, and a bounded expiry.
- Authentication credentials and session state must not be stored in browser local storage.

## Authorization and data exposure

- Authenticated mutations require a valid session and a scrapbook role checked by the server.
- Owners and editors can manage scrapbook content. Owners can remove editors and control share-link state; editors cannot remove editors or change share-link state.
- Public routes authorize with an enabled share token and never require a session.
- Public responses must not expose passwords, session data, editor emails, or other private account details.
- Authenticated preview snapshots use the same public-shaped data as sharing but require the signed-in owner/editor scrapbook role and do not expose share tokens.
- Rotating a share token supersedes the previous token. Disabling a share link prevents public scrapbook data from being returned.

## Upload and storage security

- Uploads are validated by allowed MIME type (including JPEG/JPG and QuickTime MOV), configured size limit, and file signature before a visible record is created.
- Media content is fingerprinted with SHA-256 and uniquely constrained within a scrapbook so identical files are rejected rather than silently duplicated.
- Media accepts the currently supported photo/video types; stickers accept raster JPEG, PNG, and WebP images.
- The server rejects arbitrary remote sticker URLs and does not fetch client-provided remote files.
- Storage keys are generated by the server and are never accepted directly from the client.
- The local storage adapter rejects absolute paths and path traversal outside the configured media root.
- The media root is not exposed as an unrestricted static directory.
- Temporary upload files are removed after request processing.

## Configuration and secrets

- `.env` files are ignored by Git; only example configuration belongs in the repository.
- Database credentials, session configuration, and storage paths are supplied through environment configuration.
- Security-sensitive behavior should be changed in the server boundary and covered by server tests before client controls are updated.
